# 测量条件（正式样本之前确定）

短试跑 `pilot.txt` 中 sort_a 在 4096、65536、1048576 元素的耗时分别约 0.16 ms、3.3 ms、65 ms，选择这三个规模覆盖小数组、256 KiB 数组与 4 MiB 数组。普通数据为原生成器的 [0,2^31) 域；inverted 为 N..1。共同域严格小于 UINT_MAX。

- Clang 18.1.3；正常 flags：`-O3 -DNDEBUG -g -Wall -std=gnu99 -gdwarf-3`，链接 `-lrt -lm`。不启用 LTO、march=native。
- `CLOCK_MONOTONIC`，仅包围外部排序入口，包括版本所需 malloc/free；生成、复制、检查、打印在计时之外。sum_time 每种输入单独清零，double 精度。
- seed=42；进程内部状态连续推进，各版本同试次得到相同副本；独立进程重现同一序列。`seed-check.txt` 已检查。
- 固定 `taskset -c 2`（当前可用 CPU 0..21；这是 WSL 逻辑 CPU，不推断其真实物理核心类型）。
- 正式每组 5 个独立进程，每进程 R=5；每个规模/版本先一个 R=1 预热，明确另存并排除。版本顺序逐次轮换。
- 汇总为 **5 个独立进程的平均排序耗时的中位数**，不是 25 个单次排序的中位数。保存每个原始排序耗时和进程均值。
- 两种输入分别报告，加速比为同批 sort_a 中位数 / 当前版本中位数。保留全部样本与范围，差异接近波动不声称确定收益。
- W1 Cachegrind：单版本 sort_a，seed42，random，N=32768，R=1，DEBUG=1 与 DEBUG=0 强制重建；正常耗时另测，不使用模拟运行的时间。
- 各版本 Cachegrind：同上 N/R/seed/type；明确 cache-sim=yes、branch-sim=yes。保留全进程指标和逐函数/源码指标，不能互相混称。
- Perf：软件 cpu-clock:u，999 Hz，单版本 random，与正常计时分开；保存原始 data、匹配二进制、源码和可读导出。
- W3：仅 recursive inline 提示与同代码的 noinline 诊断对照；检查调用、text 大小、Cachegrind I refs/I1/LLi、正常时间；无负面效果则直接报告。
- W5：先确定 a/i/p 中实测最快正确版本作来源；候选仅 8、16、32、64，各 5 进程/R5/三个规模/两种输入。主要依据中大规模两种输入的等权几何平均耗时比，兼看稳定性；不按最佳单次挑选。只有异常或具体问题追加。
- 全部重负载由 root 串行安排，审查代理只读。最终比较六版本同一构建与同一驱动；中间选择批次与最终批次分别保存。
