## 1. Autotuner 的三个接口

![框架设计图](images/framework.svg)

### （1）输入目标程序

[TargetProgram](src/autotuner.py) 接收 C 源码和编译器，负责构建、运行和解析结果，不决定搜索顺序。四个优化级别分别构建，分块大小通过运行参数传入；构建缓存核对源码、编译器和完整选项，并检查二进制哈希。重复搜索只复用构建，每轮测量重新运行。

### （2）输入配置参数值组合

`ConfigSpace` 保存候选值、检查合法配置，并按分块大小优先的顺序枚举组合。它不编译程序，也不根据已知性能调整枚举顺序。正式参数空间共 20 个配置。

### （3）输入搜索算法

`SearchStrategy.suggest()` 提出下一配置，`observe(config, score)` 接收本轮实际测量反馈。`Evaluator` 统一处理超时、重复测量、中位数和失败；`search()` 负责预算与搜索循环，评估器更新已测配置的当前最优，`Journal` 保存原始输出、运行成本和恢复状态。非零退出、超时、缺失或非法耗时不会被当作最快结果。

搜索循环的关键部分如下，各算法只负责提出配置和接收反馈：

```python
for trial_id in range(len(trials), budget):
    config = strategy.suggest()
    if config is None:
        break
    trial = evaluator.evaluate(config, trial_id)
    strategy.observe(config, trial["score"])
```

`len(trials)` 使恢复后的已完成试验仍占用原预算；某次测量失败时 `score` 为 `None`，不会参与最优耗时比较。恢复时保留已完成的重复，只继续尚未开始的测量；已记录的失败不重跑或覆盖。

![接口与原计算循环](images/interfaces-kernel.png)

这种划分使搜索规则可以共用目标与测量逻辑，构建也能在不同分块之间复用。调优器使用 Python 3.12.3，只依赖标准库，串行运行便于比较；限制是目标适配仍需要明确输出格式，局部搜索不保证全局最优，一次在线观测也可能受系统负载影响。

## 2. 输入的 Matrix Multiplication 程序

[原始附件](src/matrix_multiplication.original.c) 按字节保留。[运行目标](src/matrix_multiplication.c) 使用原来的六层循环、`double` 矩阵和 n=4096，初始化在计时前完成。s=24 时 4096 不能整除，但每层循环都有边界条件，末块仍参与计算。

适配只增加严格的命令行检查、计时后的结果 checksum，并将原位置的 `gettimeofday` 换为 `CLOCK_MONOTONIC`。原计时在该 WSL2 环境中与进程单调计时不一致，因而所有后续测量使用同一单调时钟。checksum 在计时区间之外计算，初始化、乘法内核和计算量保持原样；原始 O3 汇编也保留了目标计算。

数值检查直接从运行目标生成 n=128、129 的小规模版本，自动检查计算内核与附件相同，再与独立的未分块 `long double` 点积逐元素比较。五个 s、四个优化级别和六组输入共 240 个用例通过，最大绝对误差为 5.174333×10⁻¹⁴，采用 `|误差| ≤ 10⁻¹² + 10⁻¹¹×|参考值|`。n=129 的五个分块通过 ASan/UBSan 检查；n=4096 在 O0/s=24 和 O3/s=128 各抽查 24 个角点、尾部和预定随机位置，最大绝对误差为 2.937539×10⁻¹²。大矩阵抽查不等于逐元素全量比较。

## 3. 输入的配置参数值组合

### （1）循环分块大小

`s ∈ {8, 16, 24, 64, 128}`，作为目标程序的命令行参数。

### （2）编译优化级别

`O ∈ {O0, O1, O2, O3}`，作为编译参数。公共编译选项为 `-std=c11 -Wall -Wextra`，只改变 `-O0` 至 `-O3`，不添加其他优化开关。

## 4. 三种参数值搜索算法

### （1）Grid Search 与完整配置结果

Grid 按 s 外层、O 内层枚举全部 20 个组合。完整参照表则采用三轮随机化次序，每轮每配置测一次，以三次中位数排序；它与在线 Grid 的固定访问顺序分别保存。参照、在线初评与留出确认各先运行一次固定 O3/s=128 预热，预热不参与排序。

| s | O0（秒） | O1（秒） | O2（秒） | O3（秒） |
| ---: | ---: | ---: | ---: | ---: |
| 8 | 300.623230 | 77.373161 | 78.313446 | 78.263649 |
| 16 | 217.292618 | 44.326172 | 43.614208 | 44.371098 |
| 24 | 210.435379 | 46.188328 | 43.737030 | 44.067669 |
| 64 | 179.600632 | 41.472359 | 41.239479 | 41.112492 |
| 128 | 178.396179 | 41.177814 | 39.499706 | 42.501537 |

![分块大小与优化级别的耗时](images/grid_median.png)

表中及热力图为 reference_v1 的内核耗时中位数，单位为秒；n=4096，每配置三个有效样本。完整样本、最小值、最大值和 MAD 见 [配置统计表](results/summary/grid_summary.csv)。观测最优为 O2/s=128，三次为 40.385387、39.499706、34.484921 秒，中位数 39.499706 秒，MAD 0.885681 秒；它是这组观测的参照，不是无噪声真值。

O0 明显较慢，s=8 时中位数为 300.623230 秒；使用 O1—O3 后，同一分块降到约 77—78 秒。O0 汇编在内层反复从栈读取索引并计算地址，O1 使用寄存器和指针递增，这种索引与控制开销的减少与耗时下降相符。s 从 8 增大到 16 后，O1—O3 进一步降到约 44 秒，但再增大分块并非单调加速。较大分块减少外层循环与块边界检查的次数，同时改变 B、C 的局部访问范围；仅凭时间不能确定某一块大小恰好匹配缓存。

本编译条件下，四个构建的计时内核均使用标量乘加，O2 与 O3 的计时区间汇编相同，优化信息指出内层控制流阻碍了向量化；优化信息中唯一标为向量化的是计时后的 checksum 循环。O1—O3 的差异不能简单解释为“O3 使用 SIMD”，也不能认定 O3 总是最快。O1/s=128 与 O3/s=128 的相对样本范围分别为 24.32% 和 32.36%，所有快慢样本均保留，较小的性能差异需要结合复测判断。


### （2）Random Search、Greedy 与比较

Random 将 20 个配置按给定 seed 打乱，无放回访问。Greedy 从给定 seed 决定的单一起点开始，邻域是一个参数沿候选列表移动一格、另一个参数不变；邻居按配置空间稳定顺序访问。测完当前邻域后只接受严格更快的配置，平局留在原处，没有更快邻居时停止。所有起点和试探都占预算，预算在邻域中途耗尽时只返回已经测过的最好配置。

三种算法共用预算 B=8、每配置一次在线测量和三个搜索 seed；每轮返回配置另测三个新样本。seed 只改变搜索次序或起点，正式 C 程序的初始化保持相同。质量以返回确认中位数计算，成本分别统计真实进程数和完整搜索加确认的 wall time。在线曲线使用当时已获得的结果，时间横轴为框架内部反馈窗口，不包含返回确认。

质量指标为 `g=(t_found/t_ref−1)×100%`，其中 `t_found` 是返回配置三个新样本的中位数，`t_ref=39.499706 秒`；预先定义 `g≤5%` 为近优。搜索单次观测与返回确认分别保存，不把完整参照表的中位数填入过去的在线轨迹。

| 算法 | seed / 重复标识 | 返回配置 | 确认中位数（秒） | g（%） | 运行数（搜索+确认） | 完整耗时（秒） |
| --- | ---: | --- | ---: | ---: | ---: | ---: |
| Grid | 104729 | s=16/O1 | 44.194180 | +11.88 | 8+3 | 1053.20 |
| Grid | 130363 | s=16/O3 | 44.844345 | +13.53 | 8+3 | 1040.77 |
| Grid | 155921 | s=16/O3 | 42.672432 | +8.03 | 8+3 | 1006.07 |
| Random | 104729 | s=16/O1 | 48.896767 | +23.79 | 8+3 | 1082.79 |
| Random | 130363 | s=128/O2 | 33.191216 | -15.97 | 8+3 | 697.46 |
| Random | 155921 | s=128/O3 | 32.911858 | -16.68 | 8+3 | 1057.64 |
| Greedy | 104729 | s=16/O3 | 43.453590 | +10.01 | 7+3 | 526.52 |
| Greedy | 130363 | s=128/O1 | 39.124683 | -0.95 | 7+3 | 529.63 |
| Greedy | 155921 | s=128/O3 | 33.041843 | -16.35 | 5+3 | 289.01 |

表中是 selection_v1 的真实在线结果。Grid 的 seed 仅作为重复标识，三次候选次序相同；Random 和 Greedy 的 seed 决定次序或起点。完整耗时包括 Python 启动、构建检查、程序初始化、搜索与三个返回确认；四级构建已共同准备，各轮没有新增编译。按原参照计算，Grid、Random、Greedy 的近优次数为 0/3、2/3、2/3。其中部分 O2/s=128、O3/s=128 的后续确认比各自原参照低超过 12%，负 g 也不能解释为搜索创造了配置空间之外的性能。

![真实在线搜索曲线](images/online_search.png)

曲线来自 selection_v1，n=4096，在线每配置一次测量。左侧是累计评估数，右侧是搜索内部反馈窗口的秒数，纵轴为当时观测的最好内核耗时；提前结束后不补画未执行的步数。返回确认的三次新样本与完整调优成本使用上表。

Grid 在八次预算下只访问 s=8、16；这一次固定顺序使早期探索较慢，不能据此断言所有枚举顺序都差。完整遍历能覆盖每个配置，但调优成本高。Random 无放回且实现简单，有限预算的质量取决于抽到哪些配置；Greedy 的三个起点分别为 s=16/O2、s=128/O3、s=64/O3，在这些起点下较快结束，完整搜索加确认耗时中位数为 526.52 秒，Random 为 1057.64 秒，Grid 为 1040.77 秒，但局部停止可能错过更远的配置。这三个 seed 的结果不足以支持跨机器或总体最优性的结论。

另外检验两个分别基于 Random 的单项变化。优化级别分层搜索先分别打乱各 O 中的五个 s，再逐轮打乱 O 的访问次序，每层取一个尚未访问的配置；前四步覆盖四级，B=8 时每级各访问两次。它借鉴 [MLKAPS（2025）§4.1.1](https://arxiv.org/pdf/2501.05811v1) 的覆盖思想，简化为离散分层，不引入模型，也不等同于论文的完整采样方法。强制覆盖可能增加慢配置的评估成本，覆盖均衡本身不表示更快找到最优。

有限 patience 搜索保留同一 seed 的 Random 候选次序，只改变停止规则：至少测五个配置，连续三次没有超过 6% 的相对改善时停止，最多八次；任何更低的有效耗时仍会更新当前最优。关注真实调优投入的动机来自 [Just-in-Time autotuning（2023）§3.3、§4.3](https://arxiv.org/pdf/2309.06414v1)，这项具体停止规则是这里的启发式，原论文没有提出它。它可能节省运行数，也可能错过后面的好配置，因此质量和完整搜索加确认的成本必须一起比较。两个变化单独运行。

分层候选三轮都返回 s=128/O2，完整耗时中位数为 890.83 秒；相对于配对 Random，确认耗时差分别为改善 9.866047 秒、增加 3.015102 秒、改善 0.662960 秒。只有第一组达到事先设定的实质改善要求，第二组返回同一配置的时间差也受测量时段影响，不能称为稳定质量提升。Patience 共少跑七次搜索，完整耗时中位数为 664.63 秒，但 seed=130363 在第七步停止，错过第八步的 s=128/O2；返回确认中位数为 39.563389 秒，对应 Random 为 33.191216 秒，质量与成本存在取舍。

有限复测中，s=128/O2 的三个新样本中位数为 37.563213 秒；随后将 s=128/O3 与原参照最优 s=128/O2 交错各测三次，中位数为 40.802387、41.061607 秒。部分返回确认的较低耗时没有稳定保持，原参照表不替换。两个变化都没有可确认的收益，因此保留基础算法，不采用增强规则。

| ---: | --- | ---: | ---: | ---: | ---: |
| 196613 | s=16/O3 | 44.424389 | +12.47 | 8+3 | 998.79 |

### 运行方式

从仓库根目录可查看配置空间或运行搜索：

```bash
python3 P1/src/autotuner.py list
taskset -c 0 python3 P1/src/autotuner.py search --algorithm random \
  --budget 8 --seed 104729 --repeats 1 --timeout 1200 \
  --output P1/.cache/demo-search.jsonl
```

`--target` 输入源码，`--blocks` 与 `--opts` 输入候选值，`--algorithm` 选择规则；将算法换为 `grid` 或 `greedy` 即可使用另外两种基础搜索。完整测试、四级构建、单配置运行、断点恢复和保存数据的图表重生成命令见 [运行入口](README.md)。输出使用新文件，避免覆盖已有实验。
