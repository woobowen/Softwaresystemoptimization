## 1. Autotuner 的三个接口

![框架设计图](images/framework.svg)

### （1）输入目标程序

[TargetProgram](src/autotuner.py) 接收 C 源码和编译器，负责构建、运行及解析耗时。目标程序以分块值作为命令行参数，首行输出以秒为单位的正有限耗时。四个优化级别分别构建；缓存核对源码、编译器、完整选项及二进制，每次测量仍启动新进程。

### （2）输入配置参数值组合

`ConfigSpace` 接收分块和优化级别的候选列表，检查合法值并枚举组合。配置空间与搜索顺序分开，完整空间固定为 20 个组合。

### （3）输入搜索算法

`SearchStrategy.suggest()` 提出配置，`observe(config, score)` 接收刚取得的测量反馈。`Evaluator` 统一处理重复、超时和失败，`search()` 控制预算并返回已测配置的最好结果；失败、NaN、零或缺失耗时不会成为最优。

三种基础算法的反馈路径如下：

```python
config = strategy.suggest()
trial = evaluator.evaluate(config, trial_id)
strategy.observe(config, trial["score"])
```

日志记录每次目标调用，恢复时继续尚未开始的测量，已完成及失败的调用仍占预算。

![三个接口与原计算循环](images/interfaces-kernel.png)

三类接口使算法共用同一目标和评估过程，也便于增加搜索规则；Python 调优器只依赖标准库。限制是目标需要约定输出格式，串行调优成本较高，测量噪声及局部搜索都可能影响返回配置。

## 2. 输入的 Matrix Multiplication 程序

[原始附件](src/matrix_multiplication.original.c) 与老师源码一致。[运行目标](src/matrix_multiplication.c) 保持 n=4096、`double`、原初始化及六层乘法循环，使用 GCC 13.3.0 编译。s=24 时末块长度为 16，每层的边界判断保证尾块参与计算。

适配增加参数检查和计时后的 checksum，初始化及 checksum 均在乘法计时之外。内核耗时与调优成本使用 `CLOCK_MONOTONIC_RAW`，先相减整数纳秒再换算为秒。该时钟与宿主 QPC 在所测对齐区间内一致，`MONOTONIC` 和 `REALTIME` 读数作为辅助诊断保存；这项检查不能保证未来精度，也不能消除运行波动。

n=128、129 的同源版本与独立 `long double` 点积逐元素比较，五个分块、四个优化级别和六组输入共 240 个用例通过；n=129 的五个分块通过 ASan/UBSan。采用上述计时适配后，n=4096 的 O0/s=24 与 O3/s=128 各抽查 24 个预定位置，最大绝对误差为 2.937539×10⁻¹²、最大相对误差为 2.814528×10⁻¹⁵。大矩阵抽查不等于全量逐元素验证。

## 3. 输入的配置参数值组合

### （1）循环分块大小

`s ∈ {8, 16, 24, 64, 128}`，通过目标程序的命令行参数传入。

### （2）编译优化级别

`O ∈ {O0, O1, O2, O3}`。四级公共选项为 `-std=c11 -Wall -Wextra`，仅改变 `-O0` 至 `-O3`，共 5×4=20 个配置。

## 4. 三种参数值搜索算法

### （1）Grid Search 与完整配置结果

Grid 按 s 外层、O 内层完整枚举 20 个组合。完整配置参照采用三个预定随机轮次，每轮每配置测一次，共 60 个正式样本；随机次序用于减轻固定顺序的时段影响，完整覆盖不变。

![分块与优化级别的耗时](images/grid_median.png)

数值为 n=4096 的 RAW 内核时间中位数，每配置三个有效样本。完整样本、最小值、最大值和 MAD 见[配置统计表](results/goal2r_summary/grid_summary.csv)。最小中位数对应 s=128/O3，为 47.007504 秒；其三个样本为 49.688403、46.822599、47.007504 秒，MAD 为 0.184905 秒。

O0 明显较慢，s=8 时约 391 秒，O1—O3 降至约 101 秒。O0 内层反复读取栈上的索引并计算地址，O1 使用寄存器和指针递增，与控制开销减少的趋势相符。s 从 8 增大到 16 后，O1—O3 约为 63—65 秒；继续增大并非单调加速。大块减少块边界检查，也改变 B、C 的访问范围，仅凭时间不能断定缓存命中率。

这些构建的乘法内核使用标量乘加，O2 与 O3 的计时区间机器码相同，不能把 O3 解释成使用 SIMD 或必然更快。s=128/O1、O2 的中位数分别比 O3 高 0.826%、1.082%，三者样本范围重叠，不能确定唯一稳定第一。图中的范围表示实测最小值和最大值，不是置信区间。

### （2）Random Search、Greedy 与比较

Random 按 seed 打乱全部配置，无放回访问。Greedy 从 seed 决定的单一起点出发，检查一个参数沿候选列表移动一格的邻居，只接受严格更快的配置；无改善时停止，预算耗尽时返回已测过的最好配置。起点和所有试探都占预算。

六个预定 seed 分别独立运行三种基础算法，每次最多八次目标调用、每配置一次在线测量。配置差距统一为 `g_ref(c)=100×(T_ref(c)/min T_ref−1)`，其中 `T_ref(c)` 是上表中配置 c 的内核时间中位数；相同配置对应相同差距。搜索总耗时使用进程外的 RAW 计时，包含该次搜索的目标运行、构建检查和框架开销，与单次乘法内核耗时不同；外部确认与共同构建另计。

### （3）有限候选复核

候选复核策略（代码中为 `recheck`）用同 seed 的 Random 前六项探索，把最后两次调用用于首测最快的两个候选各一次复测。目标调用数仍为八次，访问的不同配置从八个减少为六个；只允许成功复测的候选返回，以首测、复测的中位数排序，两个样本时等于平均值。重复测量的动机参考[重复测量研究（2021）](https://arxiv.org/abs/2103.08716)，质量与调优时间分开比较参考[比较方法研究（2024）](https://pure.uva.nl/ws/files/182730825/A_methodology_for_comparing_optimization_algorithms_for_auto-tuning.pdf)第 3.3—3.4 节。这是本项目的有限简化，并非论文方法复现，两个样本不提供统计置信保证。

每组搜索结束后，对 Random 返回、候选复核返回和参照配置的并集测三轮，同配置每轮只测一次。计算 `G=100×(t_Random−t_recheck)/t_参照`，分母是该轮 s128/O3 的内核耗时；1 个百分点对应参照耗时的 1%，正值表示候选复核返回更快。同配置的选择差为零，其真实测量仍保留。48 次共同测量不反馈搜索，也不计入各算法的搜索总耗时。

![候选复核与同 seed Random 的比较](images/saved-search-results.png)

候选复核的配对搜索总耗时节省中位数为 25.708%，表示调优过程更短。第 1、4、6 组的三轮 G 均低于预定的 −2 个百分点损失界限，第 4、6 组还均低于 −10 个百分点，因此不保留这项策略。第 3、5 组跨过 −2 的边界，质量差尚不确定；表中范围为三轮实测最小值与最大值。

第四和第六组 Random 的第八次探索分别找到 s128/O2、s128/O3，候选复核的前六项没有覆盖这两个配置，反映了少探索的代价。第四组的两次独立搜索都访问了 s64/O1，首测分别为 51.620488、94.097100 秒，导致候选排名不同；第六组复测后则由 s24/O3 改选 s24/O2。探索范围与在线估计都影响了返回结果，不能把全部质量损失归因于减少两次探索，也不能据搜索总耗时节省推断矩阵内核加速。

### 运行方式

进入 P1 目录后执行：

```bash
python3 -B src/autotuner.py list
taskset -c 0 python3 -B src/autotuner.py search --algorithm random \
  --budget 8 --seed 700001 --repeats 1 --timeout 1200 \
  --output .cache/demo-search.jsonl
```

`--target` 输入按上述参数和输出约定适配的源码，`--blocks` 与 `--opts` 输入候选值，`--algorithm` 选择规则。四级构建和单配置运行入口见 [README](README.md)。性能比较需要稳定且可比的测量条件。
