# Goal 2 测量和选择协议

状态：APPROVED，冻结时间为2026-10-02 18:12:04 UTC。本说明与 `protocol_v2.json` 配套；新完整参照、算法比较和候选结果尚未产生。目标、框架、driver、分析器及测试的实际 SHA 固定在 JSON 中；代码关见 [runner review](reviews/goal2_runner_review.md)，方法关见 [protocol review](reviews/goal2_protocol_review.md)，分析侧独立回归见 [method/analysis review](reviews/goal2_method_analysis_review.md)，数值与核心契约见 [code gate](reviews/goal2_code_gate.md)。正式执行还须核对 [精确资源清单](measurement/resource_plan_v2.json) 及其真实剩余额度。诊断本身另用 `protocol_diagnostic.json` 和已审核的 [design.md](measurement/design.md)，不覆盖 Goal 1 协议或原始数据。

## 1. 对象、时间域与边界

目标为同源 `n=4096`、`double`、原初始化和六层分块循环，空间严格为 `{8,16,24,64,128} × {O0,O1,O2,O3}`。同一 GCC 和公共 `-std=c11 -Wall -Wextra` 参数；唯一规定的编译变量为 O。不改矩阵数据、循环、转置、并行或全局环境。CPU0 是 WSL 的逻辑 CPU，不能据此认定宿主机核型或频率。

在线分数为目标输出的 MONOTONIC 内核秒数；完整进程和搜索 driver 秒数也使用 MONOTONIC。子进程边界依次保存 MONOTONIC、RAW、REALTIME 的整数 ns，然后先作整数差再转秒。单位和域先验证，同域才检查 `kernel_s <= process_wall_s + 0.005s`。CPU 时间另记，不能替代等待时间；RAW 比率不作为旧/新成绩校正系数。

全 Goal 资源时间逐任务取三个正域差的最大值，保留各原值；倒退、非有限值或未知完成成本立即阻止继续。采用已审核的完整区间检查：逐个正常结束的正式目标进程与完整矩阵 driver 分来源、同 boot 保存 `q=RAW/MONO`，各与该来源第一个及前一个有效完整区间比较，任一 `abs(q_i/q_j-1)>0.02` 即停止、保留已发生成本并标 clock_conflict。目标进程逐样本检查，不用多调用搜索的 driver 平均遮掩某个样本变化；前缀保留观测，不与完整区间平均 q 作同性质比较。该门不能证明绝对时间准确。单进程串行，所有重任务持有 `.cache/performance.lock` 的非阻塞 flock。

同 boot 的两个 n4096 数值抽查也提供完整进程时钟历史，其身份固定在 [numeric_clock_baselines.json](measurement/correctness/numeric_clock_baselines.json)。它们使用同乘法内核、默认 seed1/mode0 和额外数学库参考检查；分析只接受该文件绑定的两个配置、源码/生成脚本/内核哈希、编译器、命令、实际 attempt/journal 及24点 CHECK 成功记录，不允许任意不同源码进入历史。这两个适配构建的秒数不进入参照、在线分数或确认表。

诊断选择按精确预定的 24 个 A/A 标签、4 个锚点及单列内核多时钟样本计算。原计划取得26个完整普通样本、1个中断、1个未启动；唯一有限补诊断另取得2个补标签、2个内核多时钟样本和8个新 A/A 样本。原 partial、含补标签及新四对分别保存，补标签之间包含真实长间隔，不能把安排差异解释成方差改善的因果证明。

按原 D/P 表，M0 为3.619541/46.976522%，M1为1.844295/13.784605%，选择 M1 和 rho14。M1四个快/中档排序差44.68–57.75%，新四组差91.52–119.03%，方向一致；完整 driver/目标进程/诊断内核相对首个及前个区间的最大 q 变化分别为1.8286/1.6794/1.8362%，均在2%内。新前缀没有再触发，但原被杀任务若完成会如何仍未知，也没有定位宿主机根因。完整关系一致不等于目标稳定：新 M 第一对同配置相差24.351654%，超过原 rho14。rho 是初始所选安排 `ceil(max(D,P))` 的有限描述，不是 CI、总体噪声界或全 Goal 5%分辨保证；新大差异保留，不反馈改变rho/5%目标/2pp风险限。不同身份的小差异通常只能不确定，同身份选择的质量映射严格相同，真实搜索成本另作有限实测比较。见 [联合原始派生](../results/clock_followup_summary_v2/summary.json) 与 [分析边界](measurement/clock_followup_analysis.md)。

## 2. 三种质量/成本数据分别使用

1. **在线反馈**：每次搜索只看该搜索此前真实进程观测，单次评价使用一个新进程。三个基础算法共用规则，S3 的复核按同一日志和预算计入；确认、锚点、参照和其他搜索不能进入策略。曲线保持当时估计，不能回填确认中位数。
2. **共同参照身份映射**：完整参照的三个新样本中位数为 `T_ref(c)`；`g_ref(c)=100*(T_ref(c)/min_c T_ref(c)-1)`。相同 c 在所有算法中映射相同。它是所测环境中的参照，不是数学真值。
3. **同块外部确认**：块内全部搜索完成、返回记录锁定后，集合为各返回配置与参照最优的并集，按配置/二进制身份去重，三轮独立新进程。返回同一配置的算法引用同一份面板；实际进程在项目账中只记一次，不修改在线返回。

参照最优按完整中位数最小、再按 s/O 规范顺序平局决定。确认由规范配置顺序开始，使用 `Random(505071+100*block+round).shuffle`，每轮完整覆盖面板。锁定文件保存全部依赖 journal SHA、参照 manifest SHA 和自身 fingerprint；不能改 summary 后复用原面板。

每个返回提供参照差距、同时段面板差距、样本和未知/冲突状态。5% 固定为近优目标；参照/确认不能辨清该目标时分类“暂无法区分”，而不是改大目标。重复运行、共享面板、六个种子均不解释为更多独立种子或总体保证。

## 3. 参照、算法次序与起点

参照三轮完整随机遍历 20 个组合，每轮使用 `Random(505063+round-1).shuffle`。每轮位置 0、10、20 后额外测 `s128/O2` 锚点，另有一次预热；60 个正式样本与 10 次辅助成本分别保存。随机访问完整覆盖，不能冒充在线有限预算 Grid 的重新排序。

主调用预算 `R=B=8`，在线每提议一个新进程，Greedy 可合法提前停止，真实次数与失败均记录。Grid 保持 block-major/opt-major 固定顺序；Random 无放回；Greedy 保持原随机起点和轴邻域规则。

主种子按 `700001+104729*i, i=0..5` 固定，留出用 `i=6..8`。算法顺序生成的精确 API 为 `list(itertools.permutations(['grid','random','greedy','recheck']))`，`rng=random.Random(505057)`；每候选布局有放回执行六次 `rng.choice(permutations)`，只拒绝位置计数 max−min>1 或 Random 在 S3 前不是三块的布局，接受第 396 个布局。未检查 Greedy 起点或性能再换 seed。

## 4. 唯一候选 S3

采用同 Random seed 的六项随机前缀探索，按首测有效秒数、再按访问顺序选最多两个 finalist，各独立复核一次；同配置两样本中位数计分，只有成功复核的 finalist 有最终返回资格。两个相同重复数候选之间比较，不把一项首测低点与另一项多样本永久历史 min 比较。

平局沿初测访问顺序；复核顺序沿首测名次；探索结束时 finalist 冻结。失败/中断占已发生调用或提议成本，不能免费补探索，复核失败不能恢复首测资格。有效候选不足自然提前停止，全部无效则无返回。恢复重放初测分数、复核和阶段，不重跑已发生进程。best 估计可随复核上升。公共接口 `budget>=4/repeats=1`，探索数为 `min(space_size,budget-2)`；正式始终为六加二。

这是有限重复分配一个因素，不加入分层、patience、起点偏好、重启或模型。相同 R 下少探索两个配置可能减少慢配置的搜索成本，也可能错过更好配置。效率路径为主要假设，质量路径为次要假设；并不要求候选产生正结果。正文借鉴与项目简化见 [literature_goal2.md](literature_goal2.md)。

## 5. 可测试的接受表

定义正收益 `G_ref=g_ref(Random)-g_ref(S3)=100*(T_R-T_S)/T_ref_best`，单位是参照最优的百分比点，不能混成相对 Random 的百分比秒差。同块面板用该块固定参照的中位数作相同点估计。

端点敏感性区间取分子 `T_R,min-T_S,max`、`T_R,max-T_S,min` 与锚点 `min/max` 四个比值的最小和最大值，分别得到未扩张 `[L_ref,U_ref]`、`[L_panel,U_panel]`；这样负分子和跨零情况也正确处理。端点只描述已测样本，不是置信区间。相同配置先判身份，两个区间严格 `[0,0]`，不从跨时段秒数构造选择质量差。

不同配置若 `d=max(0,L_ref-U_panel,L_panel-U_ref)>rho`，判参照/面板冲突，阻止 KEEP，不持续刷新参照。无冲突时支持区间为 `[min(L_ref,L_panel)-rho,max(U_ref,U_panel)+rho]`，同身份仍为 `[0,0]`。近优分类也将参照/面板 gap 上界向外加 rho、下界向外减 rho：两上界均不超过5%才是观察支持的近优，两下界都超过5%才是明显较差，否则不确定。

| 优先级/条件 | 决定 |
| --- | --- |
| 源码/协议/步骤身份错误、数值无效、缺共同确认/有效配对或真实成本未知 | INCONCLUSIVE；修复受影响路径，不批准候选 |
| 参照与面板冲突，或未能支持固定风险界 | INCONCLUSIVE；不扩大5%目标/2pp风险限 |
| 主实验或新种子确认任一配对返回不同配置身份 | INCONCLUSIVE；诊断不支持不同身份的2pp精细风险判断 |
| 任一块支持收益上界 `<-2pp` | REJECT；`<-10pp` 另标严重回归 |
| 任一块支持收益下界 `<-2pp`，但未满足明确拒绝条件 | INCONCLUSIVE |
| 全块风险通过，配对 `1-driver_S3/driver_Random` 的中位数 `>=10%` | 主效率路径获选 |
| 全块风险通过，支持收益下界中位数 `>=2pp`，至少两块下界 `>=5pp`，配对成本增加中位数 `<=10%` | 次质量路径获选 |
| 数据齐全且风险通过，两收益路径均不满足 | REJECT；保留简单 Random |

每块风险检查，不用平均数隐藏严重起点失败。新A/A已经超过初始rho，故在任何正式候选结果产生前冻结 `different_identity_risk_supported=false`：主实验或确认任一配对不同身份即 INCONCLUSIVE，仍报告全部共同参照与面板点估计/端点，不以质量路线授予 KEEP。全同身份的选择质量差严格0，10%实际成本效率路线仍可检验；这个限制不改变5%目标、2pp风险限、10%最低收益或种子。10% 是实际搜索 driver 节省，含所有内部复核和构建；调用上限相同，不据此称减少调用。浮点边界只使用 `1e-12` 机器舍入容差，不放宽实际阈值。rho较大导致不能支持2pp时为 INCONCLUSIVE，不把噪声变成允许退化。

六块选择获选后才执行三个新 seed 1328375、1433104、1537833 的 Random/S3 配对与共同确认，使用相同决策表。只看一次，不用留出调参；只有选择与确认都获选才保留 S3。未获选时候选留出为 NOT_REQUIRED，但三个新 seed 的最终基础 Random 仍真实执行与确认，单列稳定性结果。有限样本不能证明所有未来输入或时段“没有负优化”。

允许最多一个、不超过12个目标调用的追加证据批次，必须针对预定未决问题，经原审核角色核准、在未读留出前固定次序和集合；它不替代六个真实种子。没有有限追加的必要时不消耗预算。留出之后不修订候选调参。旧 S1/S2 不恢复默认，不重写旧判定。

## 7. 可复现与分析

新 `plan.json` 从冻结协议再生并完全核对 jobs；每个 journal 的源码、编译器、缓存构建身份、clock、header/fingerprint、实际 stdout、进程起止、提议、聚合和 summary 均核对。分析另独立重算四策略的在线路径、S3阶段与最终资格，不依赖最终确认回填。

正式分析一次读取指定全局账本的 bytes，同时计算 SHA 与解析记录；不以运行恢复入口的实时账本代替该快照。逐 attempt 和实际 journal 核对物理启动、原始三域 ns、保存的完整 process/driver 检查及首个/前个身份。缺字段、未知/未结束成本、完整时钟冲突均阻止 KEEP；冲突原始进程和已发生成本保留，但不计入参照/确认有效数或近优判断。

分析命令本身也受控记账时，先持锁保存所有先前任务均已结束的账本快照，`--ledger` 读取该快照，分析进程成本随后追加主账；避免自己的在途零调用任务被误当已结束。质量/选择结论注明截至哪个快照，最终项目总账另取最新完整快照。快照不修改已有记录，也不把尚未知成本填成零。

入口为 `scripts/summarize_v2.py --protocol ... --reference ... --runs ... --ledger ... --output-dir ...`；diagnostic 用匹配诊断协议单独分析。`--plots --image-dir ...` 只从原始派生表作图。派生输出不得覆盖或嵌套在 raw 批次中，NaN/零/失败不能变成最快样本。冻结后源码/driver改变时用匹配提交重算，不改旧 header/hash 或放宽身份检查。

Goal 1 在受审固定提交的忽略 detached worktree 中重算，旧 raw、协议、判定和旧派生结果只读，输出到该 worktree 的 `.cache`。最终干净复现另执行全部测试、四级冷构建和一项新 n4096，数值派生核对与原始哈希保护分别记录；新复现时间不回填正式成绩。复现目标可来自局部 clone，但目标 journal 保存到 `evidence/reproduction/goal2/` 的持久文件，保留真实源码路径与同源 SHA；清理临时 clone 后，发布版本仍能重建这次非评分运行的完整时钟历史。
