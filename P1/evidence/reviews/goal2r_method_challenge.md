# Goal 2R 方法设计的独立挑战

挑战角色：`/root/reviewer`；方法作者为另一角色，主控独占正式测量。本文件不授最终 Engineering PASS。规则可达性、完整数值与初始真实计时证据已独立审核，具备开展正式测量的条件；正式结果与成品仍待审核。

## 旧判断失当的具体原因

1. RAW/REALTIME 或 RAW/MONO 的比值是两个域之间关系；可调整辅助域改变不单独识别哪一域失效。正确性、主域测量有效性与有限样本性能判断有不同依赖，不应共用一个布尔准入门。
2. `different_identity_risk_supported=false` 在 clear-loss 与 gain 计算前返回 INC，使不同身份明显变好或变坏均不能判定；rho14 的固定外扩也使 2pp 风险目标失去现实可达性。新批次应采用具体配对的实际轮内 G 描述范围，保留旧记录。
3. A/A 具有不同真实进程，即使身份相同样本不必相同；同身份选择 G=0 是同一选择的定义，不能当作两性能分布等价或消除原波动。

## 对新方法草案的挑战与条件

方法作者提出：缺数据 INC；任一不同身份上界小于 −2pp 先 REJECT；风险跨界 INC；全部下界不低于 −2pp 后，成本节省中位数至少 10% 走效率 KEEP；否则下界中位数至少 2pp、至少两组下界至少 5pp、成本增加中位数不超过 10% 走质量 KEEP；下界不足而上界能满足质量目标则 INC；连上界也不足或成本超限则 REJECT。该执行优先序没有数学上封死不同身份正负路径，但正式代码和真实数据仍须检查。

补充条件：同身份也必须有足量真实面板、两个完整 R=8 搜索、有效正成本及源/协议/计时检查；最终 KEEP 必需新种子留出且主实验与留出均 KEEP，缺留出不能通过。同阶段每个搜索只读自身反馈，共同面板不回填搜索；driver 成本含实际内部探索、复核、构建及框架。一次 driver 成本与六 seed 描述统计没有总体置信保证。

**追加样本单调性：**保留全部旧 G，追加完整两轮后 `min(G)` 只能降低、`max(G)` 只能升高。因此已跨 −2pp 或质量界限的 INC 不会因为这一敏感性界追加而变成 KEEP 或明确退化 REJECT。有限追加可以复现/扩展具体配对观察，但不能称作自然缩窄范围或保证消解不确定。正式前须冻结是否及何时追加、风险跨界优先/宽度降序/seed 升序，最多两个配对各两整轮，全部新旧样本纳入且不重做搜索。

## 计时括界复算与文档核对

独立使用 Fraction 从旧 QPC 原整数复算：

| 原预定区间 | QPC 秒 | RAW/QPC 完整括界 |
| --- | ---: | --- |
| idle40 | 40.9477802 | [0.9999918632708111, 1.0000067128181307] |
| work8e9 | 19.3217319 | [0.9999824610962286, 1.0000167904722537] |

公式为 Linux 下界 `end_before−start_after`、上界 `end_after−start_before`；QPC 先 tick 差再除实际 Frequency，按保守两个 tick 量化外扩；比界用 Linux 下界/QPC 上界与 Linux 上界/QPC 下界。没有把往返半宽当单程误差。该证据只涵盖旧两个区间，不能代替新 6 个诊断、后续块检查或几小时稳定性。

2026-10-03 实际读取 [Linux clock_gettime 手册](https://man7.org/linux/man-pages/man2/clock_gettime.2.html) CLOCK_REALTIME、MONOTONIC、RAW 段：辅助域可调整，RAW 不受频率调整；这只是 API 语义，不证明本机准确度。实际读取 [adjtimex 手册](https://man7.org/linux/man-pages/man2/adjtimex.2.html) modes 与 NOTES：modes=0 为读取；freq/65536 为 ppm，tick 的单位为微秒，不将 CLK_TCK 等同所有时钟频率。实际读取 [Microsoft QPC](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps) managed Stopwatch、frequency、thread ambiguity、virtualization 段：QPC 非 UTC 标准，Frequency 需实查，跨线程 ±1 tick 排序不确定性需说明，同线程该排序不确定性不适用；保留两个 tick 是保守量化余量。RAW/QPC 可能共享硬件，因此只支持运行区间相对一致性。Canonical 给定 URL 的工具访问返回 Internal Error，此处未据其推断本机故障。

新协议应只用 RAW 主域端点/宽度与整个比界 [0.995,1.005] 筛查；20ms 与相对宽度 0.2% 是预定工程门而非绝对准确度或性能显著性标准。桥太宽是桥证据不足，辅助日期跳变不能自动升级成 RAW 无效。
