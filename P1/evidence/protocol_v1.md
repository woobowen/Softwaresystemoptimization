# P1 Goal 1 测量协议 v1

状态：**代码与实验设计两关口已独立批准；协议冻结后由主控串行启动正式测量**。本协议使用已完成的 n=4096 预测试和一次有界噪声诊断，资料/实验设计角色尚未读取正式全网格结果。具体字段见 [protocol_v1.json](protocol_v1.json)，其 state 和 approval 已由主控依据两关口批准设置，冻结后不修改协议 bytes。

## 1. 不变条件

正式空间是 `{8,16,24,64,128} × {O0,O1,O2,O3}`，n=4096、double、同一个冻结后的计算内核。四级编译除 O 外的公共选项一致，不加入额外优化。JSON 已记录目标/框架源码哈希、编译器完整路径、版本及二进制 SHA、公共编译参数、空间和统计规则。每批计划另记录 experiment.py SHA；execute/resume 必须匹配。summarize.py SHA 记在派生摘要中，不参与构建缓存。

所有正式高负载程序由主控串行执行；实验设计角色不自行启动 n=4096。构建复用与测量复用分开：四种构建允许统一复用，独立搜索不复用网格或其他搜索的性能测量。Grid 参照、真实在线 Grid 和离线回放分别标识。

参照每配置三个有效正式样本，以中位数排序；原始失败/慢样本均保留。在线共同 r=1 已依据预测试成本确定；r=2 仅保留事前成本比较，不执行。每个搜索返回配置统一再测三个新样本，中位数用于质量比较；留出阶段规则相同。内核时间、进程 wall、编译时间和调优总 wall 分开。三个主要阶段开始各固定运行一次 O3/s128 预热；保留 raw 和真实成本，排除参照排序、在线成绩和返回确认。

旧 gettimeofday 预测试因与 Python CLOCK_MONOTONIC 的计时比例不一致仅作诊断；CLOCK_MONOTONIC_RAW 是后续探针涉及的钟域，不是旧内核计时器。新目标只将原计时点改为 CLOCK_MONOTONIC，原六层计算循环和 float 输出保持；新预测试与有界噪声诊断已完成，阈值据此确定。框架和分析共同拒绝 `kernel_s > process_wall_s + 0.005` 的评分，保留 stdout、时间戳及失败记录，不剔除单纯较慢的有效样本。

## 3. 候选机制

- **S1**：O 分层无放回。四层内部各随机打乱五个 s，每轮随机打乱四个 O 后各访问一个未测 s。只改候选顺序，B、r、评分、预算和确认均与 Random 基线一致。
- **S2**：同 seed 的 Random 列表前缀，最少 k_min=5 次、patience=3；相对前一步 best 的改善超过 δ=0.06 时计数清零，否则加一，达到两项条件即停。只改停止规则。它是本项目有限预算启发式，没有最优停止保证，可能错过后续优配置。

两项分别对照同一基线，不执行 S1+S2。本协议采用 B=8、r=1；不在正式数据产生后改预算、重复数或候选机制。r=2 仅保留事前成本比较，不执行重复分配后备。

## 4. 数量预算

共同 Random 基线供两项配对比较，只执行/计费一次。选择阶段包含五个版本、三个探索 seed，共 15 次真实搜索和 15 组返回确认。下表是事前计数比较，实际采用8/1：

| B / r | 五版本搜索上限 15Br | 返回确认 45 次 | 选择阶段上限（不含预热） |
| --- | ---: | ---: | ---: |
| 6 / 1 | 90 | 45 | 135 |
| 8 / 1 | 120 | 45 | 165 |
| 6 / 2 | 180 | 45 | 225 |
| 8 / 2 | 240 | 45 | 285 |

两项 KEEP 时留出搜索与返回确认上限 `9Br+27`，一项 KEEP 为 `6Br+18`，零项为 `3Br+9`。B8/r1 全 KEEP 的正式普通测量上限是 `60+165+99+3次预热=327`。另预留最多 18 次参照冲突诊断和 15 次失败进程额度，总 cap 为 360 次；失败已占用的进程不能从计数删除。正确性检查、新旧预测试另列真实成本，不冒充正式样本。

整体 wall cap 为 16 小时、单次超时 1200 秒；依据预测试的有限成本估算选择 B8/r1，粗估约10.09小时，不能保证实际任务必在 cap 内完成。统一构建的真实准备成本单列，缓存命中记 0 次编译，不隐藏发生过的编译。每次启动前检查剩余进程额度，恢复只预留尚未启动的次数；整批共用一把锁，禁止多 driver 重叠。

## 5. 指标与接受规则

质量采用返回三次新确认的中位数 t_found 和原三轮全网格观测最优 t_ref，`g=(t_found/t_ref−1)×100%`。配对收益定义为 `gain_pp=g_Random−g_candidate`，单位是百分点，正值表示候选改善。ε、η_quality、Δ_allow 均用 g 的百分点；patience δ 用 `[0,1)` 相对耗时改善比例。保存每 seed 的 g、近优命中及全部样本，不用平均值掩盖一次严重退化。

接受规则的成本采用 driver 完整 CLI 外部 wall：同 task 所有已知 attempt 的 driver_wall_s 求和，search 与三次返回确认再相加。它包括 Python启动、参数解析、编译探针、构建、运行、日志和退出；其中任一 driver actual wall unknown 时不能用内部窗口或资源上界补成已知成本。框架内部 tuning_wall_s 从解析后到搜索结束，保留独立列；在线 trial 曲线 x 使用该内部 feedback 窗口，不冒称完整 CLI wall。预热和参照诊断计入项目成本，不当搜索成绩。

| 固定数值 | 解释 |
| --- | --- |
| ε=5% | 事前近优目标，不是噪声宽容或可靠分类概率。 |
| η_quality=12pp 且 5.6 秒 | 6 个 fast 预测试的相对 MAD≈5.93%，两倍向上取 12pp；绝对 MAD 两倍≈5.53 秒，向上取 5.6 秒作第二门槛。百分点映射以约46.63秒 pilot 尺度校准；正式 t_ref 不同时仍同时要求秒数 floor，不声称统计置信度。 |
| Δ_allow=2pp | 严格风险约束，不因已观察噪声增大而扩大，不是噪声 CI。 |
| δ=0.06 | 约一个描述性相对 MAD 的项目停止启发式，不是论文原算法或抗噪保证。 |
| 中位数 wall 增幅≤10%；η_wall=40秒 | S1 控制时间成本；S2 还须至少两个 seed 少一个真实完整配置评估。40秒略低于 pilot 最快内核41.61秒，作为实际节省目标，不称全20配置的最小运行时间。 |
| noise range=0.18；conflict difference=0.12 | 诊断门槛，分别略高于6个 fast 描述性 range≈17.4%和两倍相对MAD。它们不能认证2pp非劣。 |

每个配对三次确认的端点形成描述性收益范围：秒数 `[Random_min−S_max, Random_max−S_min]`，两端各乘 `100/t_ref` 得百分点范围。这是所观察样本的敏感性检查，**不是 CI、总体噪声界或显著性检验**。完全位于 −2pp 坏侧时 REJECT，跨过 −2pp 风险边界时 INCONCLUSIVE；只有全部三对 lower≥−2pp 才满足风险约束，等号计为满足。

计算 gain_pp 使用直接秒差乘 `100/t_ref`，避免两次 g 相减的浮点消去。含等号的质量、成本和诊断门用 `isclose(rel_tol=1e−12, abs_tol=1e−12)` 只覆盖机器舍入，远小于 C 输出的1e−6秒精度；该数值不是测量噪声容差。

S1 的接受规则：至少两个配对 seed 的 lower 同时达到 12pp 与 5.6 秒；全部三对满足风险约束；搜索进程数与 Random 相同，中位数总 wall 增幅≤10%。第三对仅跨收益门而风险安全，不额外否决。若可达门槛的 upper pair 也不足两个，明确 REJECT；若 upper 仍可能但 lower 不足两个，则 INCONCLUSIVE，不能凭 median 过门 KEEP。未出现实质改善时不能因覆盖较均衡而 KEEP。

S2 的接受规则：全部三对风险 lower≥−2pp，基于 median g 的近优命中数不减；至少两个 seed 节省一个配置的完整评估成本，中位数 search+return wall 至少节约40秒。近优计数只是实测中位数描述，不声称统计分类保证。两机制若实际次数/中位数 wall 已明确违反成本约束，优先 REJECT；unknown wall 为 INCONCLUSIVE。明确坏侧的风险也优先 REJECT；不使用加权总分。

选择 KEEP 后在预定三留出 seed 上重复相同规则。最终保留条件是选择与留出均 KEEP；任一阶段 REJECT 则回退 Random，INCONCLUSIVE/未完成则不声称保留改进。两项均通过时分别保留两个单项接口和比较，不合并、不再用事后加权分数选赢家。没有额外选择 seed；三 seed 仅构成小样本描述，不支持显著性或跨机器结论。

## 6. 噪声、参照冲突与恢复

原参照各配置及每组三次返回确认的相对 range 为 `(max−min)/median`。只对原参照最优配置、该候选及配对 Random 的返回配置应用18%噪声 gate；无关慢配置的噪声仍报告，不独自否定明显质量差。原参照不完整或相关配置越过该 gate 时质量判定为 INCONCLUSIVE，明确违反次数/实际 wall 成本的 REJECT 保留并附诊断标记。所有原样本保留，noise 追加次数固定0。

若返回三次确认中位数与原参照同一配置中位数的相对差超过12%，触发参照冲突。按教师规范空间次序选最多两个选择阶段冲突配置、一个留出阶段冲突配置，共至多三事件。每事件对「返回配置」和「原参照最优配置」各测三个新样本，按 A/B、B/A、A/B 交错；若两配置相同则只测三次。每事件最多6次、全项目至多18次；未被额度覆盖的冲突仍保留状态。derived conflict_request 生成计划，request SHA 同计划保存。

冲突追加只形成诊断表，**原 t_ref 和返回三次确认分数均不替换**。新参照最优配置中位数相对原值也超过同阈值时标记环境漂移；返回配置新值偏离原确认时标记返回不稳定。受冲突影响的候选阶段为 INCONCLUSIVE；诊断有助解释原因，不用于反复复测直到 KEEP。原参照表和诊断表同时保留，明确 3 样本、长批次时间漂移的局限。

失败/超时/clock_error 保留全部原记录，停止并诊断，无自动重测或删除慢样本。最多三次自主定位/修复；改变目标、编译参数或测量规则须新协议/批次，不能混用旧分数。15 次失败额度只是资源预留，不授权无限重试；未完成任务须报告未完成。

graceful interrupt 的 driver 和框架均记录实际已知时间，可在同 fingerprint 下继续未完计划。hard exit 使用 `recover --recovery-evidence`：诊断 JSON 需对应 protocol SHA、task、attempt_id、`verified_no_live_processes=true` 和实际进程检查日志路径；runner 仍拒绝已记录 PID/进程组存在时恢复，不自动 kill 其他进程。`task_recovery.driver_wall_s=null`，保存已记录子进程成本下界以及同 boot monotonic 跨度的资源上界（包含停机等待，不称实际调优耗时）；缺少 summary 时再保守占用至多一次未知 spawn 额度。跨 reboot 或不完整 task_start 无法恢复上界时停止，保留诊断，不伪记 0。未记录的实际调优 wall 不能通过成本接受条件。

## 7. 预测试依据与执行接口

已逐记录重解析 9 个新预测试与 3 个有界诊断，排除预热后 slow O0/s8 有三个样本，fast O3/s128 有六个样本。O0 中位数310.77秒、range2.48%；fast 中位数46.63秒、MAD2.76秒、range17.40%。O1/s24、O2/s24 各仅一个样本，分别44.06、42.90秒。CPU0诊断接近完全忙，资源快照未发现其他高负载；频率与温度不暴露，原因不能确定，不再循环诊断直到低噪声。

全部计分与调优 wall 使用 CLOCK_MONOTONIC，UTC/RAW/rusage 等不同钟域只作诊断，不能混加或替换正式成绩。六个 fast 样本不是独立置信区间，不能宣称 r=1 或两次重复可靠消除噪声。

按四 O 各一个 pilot 代表值等权，内核平均约111.09秒；将全部普通次数同样等权估算，B8/r1 327次约10.09小时，B8/r2 519次约16.02小时，B6/r2 423次约13.05小时，尚未加失败/冲突/准备成本。返回配置可能较快，实际可低于该粗估；其他 s 未逐一预测，不能称20配置完整成本模型。选择 B8/r1 留出诊断余量，B6/r2仍不能用两样本建立可靠CI，且预算更贵。

主控在批准后运行 `experiment.py plan --stage reference|selection|holdout --output-dir ...`，随后 execute/status/resume；holdout 必须显式给 selection KEEP 的 `--algorithms` 子集。`summarize.py --reference ... --runs ... --output-dir ... --plots ...` 重解析 raw，中位数/成本/曲线独立生成，表和图不得写入 registered raw 目录。冲突阶段采用 `--stage conflict_selection|conflict_holdout --conflict-request ...`。历史 clone 分析只按 plan 的 measurement_root 重建当时 source/cache 路径，其余 metadata/fingerprint 与当前源码 SHA 仍严格一致；实际 execute/resume 只能在原测量路径。
